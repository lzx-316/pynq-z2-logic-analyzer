# 报告提纲：PYNQ-Z2 四通道逻辑分析仪

## 1. 摘要

一句话说明作品定位：在 PYNQ-Z2 上用 PL 实现 4 通道 1 MSa/s、2048 点环形缓冲的数字逻辑分析仪，PS 侧用 Jupyter Notebook 完成控制、回读与波形显示。

关键指标：4 通道、1 MSa/s、2048 点、预触发 256 / 后触发 256、三种边沿触发、时序全部收敛（WNS 10.552 ns）、LUT 占用 3.55%。

## 2. 项目背景与目标

说明为什么做逻辑分析仪：调试数字电路时需要同时观察多路信号并定位触发时刻的时序关系。给出本项目的目标与范围边界（采样率固定、深度固定、触发只有三种边沿）。

## 3. 系统总体架构

画一张数据流图：探针输入 → 同步器 → 采集引擎 → BRAM → AXI → PS 侧 Notebook；控制流为 Notebook → AXI GPIO → 控制字 → 采集引擎。

说明软硬件分工：PL 负责实时采样与触发，PS 负责配置、回读、显示与导出。

## 4. 硬件设计

逐个模块介绍（每个模块配端口表和一段关键代码）：

`sync_4ch`：两级触发器打拍，处理异步输入与亚稳态。

`sample_divider`：50 MHz 分频到 1 MSa/s，输出单周期采样使能。

`capture_engine`：五状态机、环形缓冲、触发判定、trigger_ptr 与 done。

`logic_analyzer_top`：位域解析、测试模式选择、BRAM 字节地址拼接、状态字组装。

寄存器映射表：控制字 ctrl 与状态字 status 的位域定义。

## 5. 软件设计

Notebook 流程：加载 Overlay → 组装控制字 → clear 复位 → arm 启动 → 轮询 done → 读 trigger_ptr → 按环形缓冲还原顺序 → 四通道阶梯图 → 导出 CSV。

重点解释两处逻辑：为什么用 done 而不是固定延时；为什么按 `(trigger_ptr - PRE_TRIGGER) % DEPTH` 做循环移位才能还原正确时间顺序。

## 6. 验证与测试

仿真验证：测试平台用例、PASS 打印与波形截图（对应 TBD-001）。

实现结果：时序报告（建立余量 10.552 ns、保持 0.038 ns、脉宽 9.020 ns，约束全部满足）、资源报告（LUT 1891 / 3.55%、寄存器 2648 / 2.49%、BRAM 2 块）、DRC 全布线通过。

上板验证：内部测试模式 TEST_MODE=1 下的采集截图与 CSV 数据（对应 TBD-003 及复跑记录）。

## 8. 问题与改进方向

采样率固定为 1 MSa/s，可通过参数化分频比支持多档；缓冲深度受 BRAM 限制，可扩展到更大深度或分级存储；时间戳 28 位在 1 MSa/s 下约 268 秒回绕，长时间采集需要扩位；Pmod 外部输入通道尚未做完整验证，后续补充信号发生器测试。
